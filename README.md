> ## ⚠️ 刷机有风险，谨慎操作
>
> 本仓库所述操作会**改写相机系统文件**，操作不当可致相机无法开机。
>
> - **已记录 1 例不可恢复的变砖**：同机型、同为固件 Ver.1.00，写入后进入启动崩溃循环，USB 无法枚举，电源开关失效，需硬件级恢复（详见第四节「已发现的问题」）。
> - **本仓库不包含救砖能力**。相机完全无法开机时，不存在已验证的恢复路径。

> - 仅适用于 **Sony ILCE-6100 固件 Ver.1.00**。**固件版本号相同不代表构建相同**；目标构建不在已知集合内时，禁止写入。
> - 本仓库为技术研究用途，不提供任何可用性保证。设备所有者应在每次写入前明确知情，并单独做出确认。

## 二、使用方法：以文档为准，逐节执行

本仓库不提供一键式写入程序。推荐做法是将 `A6100-UNLOCK-OPERATIONS-GUIDE.md` 交由具备本地命令执行能力的 AI（建议附带终端），由 AI 完成只读读取、哈希计算与候选生成，由操作者逐项确认并执行写入。

1. **将指南全文提供给 AI**，并附上指南 §0 的开场句：
   > "我的目标是先检查这台相机。请按文档逐节执行：先确认机型与固件版本、准备 Windows 环境，读回校验通过后再与我确认是否继续。"

2. **自 §0 起逐节执行，不得跳节**：
   - §0 三项前置条件：核对型号与固件 → 准备 Windows 与 USB → **验证服务通道可用**（只读读回 CC、VU2 与启动脚本，并核对 MD5）。
   - §2 列出关键指针与文件；§2.3 的 MD5 表即**放行基线**。
   - §3 / §4 / §5 分别对应 Fn 替换、主菜单替换、伽马显示辅助；三项动作相互独立，可分别验收。
   - §10 为安装与写入校验；§8 为恢复；§7 为冷启动验收。

3. **放行条件须全部满足**：CC、viewUnified2、启动脚本的哈希必须命中文档已知集合。任一未命中即表示构建状态未知，应**立即停止，不得写入**（参见 §2.3）。

4. **每次持久写入前须单独确认**。确认之前应核对：操作内容、菜单层面的变更代价、回滚材料、写入前哈希复核（§10.3）。

5. **写入后执行冷启动验收**（§7）：断开 USB → 关机并取出电池、静置不少于 60 秒 → 装回电池并开机；分别验证 Fn 入口、主菜单颜色页、伽马显示辅助页，以及断电重启后的持久性。

6. **恢复操作见 §8**：按只读盘点 → 单项撤回 → 读回复核的顺序执行；异常情况按 §8.8 处理。

> **交互准则**：AI 每次仅提供当前步骤、预期窗口与预期输出，取得结果后再行推进；不得一次性下发多条命令，也不得以「先执行、后判断」的方式推进。

## 三、删除 exe 的原因

此前发布的 `PPUnlock-Offline-vX.Y.Z.exe` 是**面向单一构建的自动化写入器**：内置固定的 CC/VU2 哈希、符号值与偏移，将「盘点 → 门禁 → 写入 → 恢复」压缩为菜单式流程。删除原因如下。

1. **无法识别「版本号相同、构建不同」的情形。** 本次事故设备与原验证设备同为 Ver.1.00，但数据段整体平移 `0x10`、文件长度减少 60 字节。自动化工具只能依据固定基线比对：或直接拒绝（操作者无从得知原因与后续步骤），或在门禁被绕过之后仍按旧偏移写入，最终导致不可恢复的启动循环。
2. **单步执行缺少可审计的中间证据。** 该工具不提供逐步 MD5、符号表条目、写入前原值与读回结果；一旦发生问题，既无法定位，也无法在写入之前中止。
3. **风险集中于一次操作。** 文档路线在每一步均设有读回证据与人工确认点；exe 路线将这些检查合并省略，某一环节判断失误后即无补救窗口。
4. **维护成本与安全性不成比例。** 每出现一个新的构建，exe 均需重新出包并重新加密知识；正确的做法是**先确认构建身份**，再决定是否写入。

**结论**：在建立可靠的多构建校验机制（符号布局与数据段指纹）之前，不再分发任何自动化写入器；仅保留可由 AI 逐条复核的文档。

## 四、已发现的问题

### 4.1 变砖事件：不同构建上的 Fn 补丁导致启动循环

**报告日期**：2026-11-20 ｜ **设备**：ILCE-6100（非 6100A）｜ **固件**：Ver.1.00（机身菜单与 PMCA 均确认）｜ **产品代码**：0032850925

该用户按文档执行 PP 解锁中的 Fn 部分。只读盘点显示本机构建的 `CautionConfig.so` 与 `viewUnified2.so` 哈希**不在文档已知集合**；按 §2.3 / §3.1 的规定本应停止，但该用户在知情后依据符号表为本机构建重新推导参数，并执行了写入。

| 对象 | 文档已知值 | 事故机实际值 |
|---|---|---|
| `CautionConfig.so` 原版 MD5 | `53da30186733ca6bd09cb23318460096` | **`a19110bd3d3dc7c45b4437a0cbba4839`** |
| `CautionConfig.so` 大小 | 12,078,712 B | **12,078,652 B**（少 60 B） |
| `viewUnified2.so` 原版 MD5 | `db3119d79d1fca4b7875baf7940e87af` | **`51d0bc24bb12ed7af3adc7ded6ce2953`** |
| `startBTCore.sh` | — | `195674f003489c1e5ece1caed0700b09`，1283 B，原厂无 hook |
| `cmnViewSettingNodeRootSoftSkin` | `0xc5b5d8` | **`0xc5b5c8`**（−0x10） |
| `cmnViewSettingNodeRootPictureProfile` | `0xc5d540` | **`0xc5d530`**（−0x10） |

**过程与结果**：设备内备份、候选构建、写入与读回校验均报告通过（修改后 MD5 `a91f2f2871b5abf6d468cfa9661fc0f0`，`0x138b4c` 处为 `30 d5 c5 00`）；冷启动后屏幕呈「亮 → 黑 → 亮」循环，电源开关失效，USB 仅周期性出现 `054C:0994`（充电/关机 HID），无 `0D12` / `0336` 窗口，原版备份 `cc.bak` 留在 `/setting` 但已无法取出。

**结论**：

- **同版本号不等于同一构建**。Ver.1.00 至少存在数据段不同的构建。
- **偏移可复用不等于指针可替换**。本机 `0x138b4c` 偏移仍然成立，但两个符号的 `st_value` 均低 `0x10`；按旧目标值写入即指向错误数据。
- **门禁命中是唯一放行条件**。对未知构建的正确结论是「未验证构建，禁止写入」，而非「重新推导参数后再写入」。
- **设备内备份不构成回滚材料**。相机无法启动时，`/setting` 中的备份即无法取出；缺少完整主机镜像时不应写入。

### 4.2 报告附带的操作层问题（同样适用于文档路线）

| 问题 | 现象 | 应对 |
|---|---|---|
| PMCA `pull` 中断 | v0.18 Windows 控制台在约 1 MB 处中断（libusb0 通道），无法取到 12 MB 完整镜像 | 缺少完整、可校验的主机镜像时**禁止写入**；改用分块读取加 MD5 校验 |
| BusyBox `dd` 截断 | BusyBox 1.29 的 `dd` 无 `conv=notrunc`，带 `seek` 会 `ftruncate` 输出文件 | 设备端统一采用「完整候选文件 + `cat candidate > target`」，保留 inode 与权限 |
| 服务会话一次性 | 每次 `serviceshell` 结束即停在 `0336`，再次认证报 libusb0 错误 31，只能断电 | 每次会话自 `0D12` 开始；尽量合并操作 |
| 终端启用偶发失败 | 约半数会话中 `setTerminalEnable` 返回空错误 | 重试或重开会话，避免连续重发切换请求 |

## 五、红线（任一情形出现即终止操作）

- 目标文件哈希不在文档已知集合内；
- 主机侧缺少完整、可校验的原厂镜像或回滚材料；
- 启动脚本存在混装标记、边界不明确或已被第三方修改；
- 写入后读回不一致、连接中断或出现短写；
- 存在「重新推导参数后应当仍可写入」的判断。

---

## 六、已执行写入或相机出现异常

- **仍可开机**：按 §8 先执行只读盘点，再按单项恢复流程处理；不得为「修复」而重复写入。
- **启动循环 / USB 无法枚举**：本仓库**没有**已验证的救砖方案，需硬件级恢复。请保留屏幕状态与日志、设备身份信息（机型、固件、产品代码、已写入文件的 MD5、偏移与原值），整理为 issue 反馈；完整构建样本的收录亦有助于后续建立多构建校验。

## 七、完整性校验

```powershell
certutil -hashfile A6100-UNLOCK-OPERATIONS-GUIDE.md SHA256
certutil -hashfile README.md SHA256
```

输出应与 `SHA256SUMS.txt` 中对应条目一致（该文件另含 `LICENSE` 一行）。该文件仅覆盖本仓库自身文件，不包含任何 exe。

行尾由 `.gitattributes` 固定为 LF，Windows 与 Linux 下所计算的哈希应当一致；若不一致，说明本地文件已被改动。
