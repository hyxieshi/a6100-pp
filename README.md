# A6100 解锁（Sony ILCE-6100 Ver.1.00）— 文档版

> ## ⚠️ 刷机有风险，谨慎操作
>
> 本仓库内容会**改写相机系统文件**，操作不当会导致相机无法开机。
>
> - **已发生 1 例不可恢复的变砖**：同类机型、同为固件 Ver.1.00，写入后进入启动崩溃循环，USB 无法枚举，电源开关失效，需硬件级恢复（详见第四节「已发现的问题」）。
> - **本仓库不含救砖能力**。完全无法开机时，没有已验证的恢复路径。
> - **恢复 / 撤回流程未经真机完整实测**，只保证按设计校验，不承诺实机恢复成功。
> - 仅面向 **Sony ILCE-6100 固件 Ver.1.00**，且**同版本号不代表同一构建**——构建不在已知集合时禁止写入。
> - 测试版，后果自负，仅供学习研究。设备所有者须在每一步写入前明确知情并单独确认。

## 二、使用方法：交给 AI，按文档一关一关走

不要再指望双击一个程序自动刷完。正确姿势是把文档交给一个**能执行本地命令的 AI**（最好带终端），由它负责读文件、算哈希、生成候选，由**人**负责确认和动手。

1. **把 `A6100-UNLOCK-OPERATIONS-GUIDE.md` 全文交给 AI**，并附上文档 §0 的开场句：
   > “我的目标是先检查这台相机。按文档一关一关来，先教我确认版本和准备 Windows 环境，读回校验通过后再和我确认是否解锁。”

2. **从 §0 开始走，不许跳关**：
   - §0 三关：核对型号/固件 → 准备 Windows 与 USB → **证明服务通道可用**（只读读回 CC、VU2、启动脚本并核对 MD5）。
   - §2 关键指针与文件；§2.3 的 MD5 表就是**门禁基线**。
   - §3 / §4 / §5 分别对应 Fn 替换、主菜单替换、伽马显示辅助，三条动作独立、可分别验收。
   - §10 安装与写入校验；§8 恢复；§7 冷启验收。

3. **门禁必须全绿才动手**：CC、viewUnified2、启动脚本的哈希必须命中文档已知集合。任何一项不在集合内 = 状态未知 = **停止，不许写入**（§2.3 原话）。

4. **每项持久写入前单独确认 `YES`**，确认前先看：操作内容、菜单代价、回滚材料、写前哈希复核（§10.3）。

5. **写完冷启验收**（§7）：断开 USB → 关机取电池静置 ≥60 秒 → 装回开机。分别验证 Fn 入口、主菜单颜色页、伽马辅助页、断电重启后的持久性。

6. **要恢复就看 §8**，按只读盘点 → 单项撤回 → 读回复核的顺序；异常按 §8.8 处理。

> **交互原则**：AI 每次只给当前一步、明确窗口和预期输出，拿到结果后再推进。不要一次给一长串命令，也不要“先试试再说”。

## 三、为什么删除 exe

之前发布的 `PPUnlock-Offline-vX.Y.Z.exe` 是一个**面向单一构建的自动化写入器**：内置固定的 CC/VU2 哈希、符号值和偏移，把「盘点 → 门禁 → 写入 → 恢复」压成菜单式的一键流程。撤下的原因：

1. **它无法判断“版本号相同但构建不同”。** 本次事故机与原验证机同为 Ver.1.00，但数据段整体平移 `0x10`、文件小 60 字节。自动化工具只会拿固定基线去比对，要么直接拒绝（用户看不出原因、也不知道下一步），要么被引导绕过门禁后仍按旧的固定偏移写入——结果就是不可恢复的启动循环。
2. **黑盒一步执行缺少可审计的中间证据。** 没有逐步 md5、符号表条目、写前原值、读回结果，出问题时无法定位，也无法在“写之前”叫停。
3. **把风险集中在一次点击上。** 文档路线里，每一步都有读回证据和人的确认点；exe 路线把这些检查压缩掉了，一旦某一环判断错误，后面没有补救窗口。
4. **维护成本与安全不成正比。** 每出现一个新构建，exe 就要重新出包、重新加密知识；而正确的做法是**先证明构建身份**，再决定是否写入。

**结论**：在建立起可靠的多构建校验（符号布局 + 数据段指纹）之前，不再分发任何自动化写入器。只保留可被 AI 逐条复核的文档。

## 四、已发现的问题

### 4.1 变砖事件：不同构建上的 Fn 补丁导致启动循环

**报告日期**：2026-11-20 ｜ **设备**：ILCE-6100（非 6100A）｜ **固件**：Ver.1.00（机身菜单与 PMCA 均确认）｜ **产品代码**：0032850925

该用户按文档执行 PP 解锁的 Fn 部分。只读盘点时发现本机构建的 `CautionConfig.so` 与 `viewUnified2.so` 哈希**不在文档已知集合**；按 §2.3/§3.1 本应停止，但其在知情后基于符号表为本机构建重新推导了参数并写入。

| 对象 | 文档已知值 | 事故机实际值 |
|---|---|---|
| `CautionConfig.so` 原版 MD5 | `53da30186733ca6bd09cb23318460096` | **`a19110bd3d3dc7c45b4437a0cbba4839`** |
| `CautionConfig.so` 大小 | 12,078,712 B | **12,078,652 B**（少 60 B） |
| `viewUnified2.so` 原版 MD5 | `db3119d79d1fca4b7875baf7940e87af` | **`51d0bc24bb12ed7af3adc7ded6ce2953`** |
| `startBTCore.sh` | — | `195674f003489c1e5ece1caed0700b09`，1283 B，原厂无 hook |
| `cmnViewSettingNodeRootSoftSkin` | `0xc5b5d8` | **`0xc5b5c8`**（−0x10） |
| `cmnViewSettingNodeRootPictureProfile` | `0xc5d540` | **`0xc5d530`**（−0x10） |

**过程与结果**：设备内备份、候选构建、写入、读回校验全部“通过”（改后 MD5 `a91f2f2871b5abf6d468cfa9661fc0f0`，`0x138b4c` 处为 `30 d5 c5 00`）；冷启动后屏幕亮→黑→亮循环，电源开关失效，USB 仅周期性出现 `054C:0994`（充电/关机 HID），无 `0D12`/`0336` 窗口，原版备份 `cc.bak` 留在 `/setting` 但已无法取出。

**关键教训**：

- **同版本号 ≠ 同一构建**。Ver.1.00 至少存在数据段不同的构建。
- **偏移可复用 ≠ 指针可替换**。本机 `0x138b4c` 偏移仍然成立，但两个符号的 `st_value` 都低 `0x10`；按旧目标值写入就指向了错误数据。
- **门禁命中是唯一放行条件**。未知构建的正确标记是「未验证构建，禁止写入」，不是「重推导参数后再写」。
- **设备内备份不是回滚材料**。相机起不来时，`/setting` 里的备份等于取不出；没有完整主机镜像就不该写入。

### 4.2 报告附带的操作层问题（同样适用于文档路线）

| 问题 | 现象 | 应对 |
|---|---|---|
| PMCA `pull` 中断 | v0.18 Windows 控制台在约 1 MB 处中断（libusb0 通道），取不到 12 MB 完整镜像 | 没有完整、可校验的主机镜像时**禁止写入**；改用分块读取 + MD5 校验 |
| BusyBox `dd` 截断 | BusyBox 1.29 的 `dd` 无 `conv=notrunc`，带 `seek` 会 `ftruncate` 输出文件 | 设备端统一用「完整候选文件 + `cat candidate > target`」，保留 inode/权限 |
| 服务会话一次性 | 每次 `serviceshell` 结束停在 `0336`，再次认证报 libusb0 错误 31，只能断电 | 每次会话从 `0D12` 开始；尽量合并操作 |
| 终端启用偶发失败 | 约一半会话 `setTerminalEnable` 返回空错误 | 重试或重开会话，不要连续重发切换请求 |

## 五、红线（任一命中即停，不要“绕过试试”）

- 目标文件哈希不在文档已知集合；
- 没有主机侧完整、可校验的原厂镜像 / 回滚材料；
- 启动脚本存在混装标记、边界不明或被第三方改过；
- 写入后读回不一致、断线、短写；
- 你正在想“参数重推导一下应该也能写”。

## 六、如果你已经刷过 / 相机出现异常

- **还能开机**：按 §8 先做只读盘点，再按单项恢复流程处理；**不要**为了“修好”而重复写入。
- **启动循环 / USB 无枚举**：本仓库**没有**已验证的救砖方案，需要硬件级恢复。请保留 screen/日志、设备身份（型号、固件、产品代码、已写入文件的 MD5、偏移与原值），整理成 issue 反馈；对完整构建样本的收录，也有助于后续建立多构建校验。
